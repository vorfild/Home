# Домовой

Self-hosted PWA для семейных дел, покупок, хранения вещей и обслуживания дома. В проекте завершены
основа, семейная авторизация, дела, покупки, кладовая, обслуживание, календарь, уведомления,
настройки и Этап 8: realtime, ограниченный офлайн и явное разрешение конфликтов.

## Быстрый запуск

Требования: Linux, Docker Engine и Docker Compose v2.

Перед первым локальным запуском создайте закрытый `.env`, затем поднимите стек:

```bash
./scripts/setup-env.sh http://localhost
docker compose up -d --build --wait
```

Откройте <http://localhost>. Проверки API:

```bash
curl http://localhost/health/live
curl http://localhost/api/v1/health/ready
curl http://localhost/api/v1/setup/status
```

При первом открытии мастер предложит выбрать часовой пояс, создать администратора, назвать дом и
выбрать каналы уведомлений. Публичной регистрации нет: после мастера новых взрослых и детей создаёт
администратор в разделе «Семья».

Для установки на сервер сначала создайте закрытый `.env` с уникальными секретами, указав IP:

```bash
./scripts/setup-env.sh http://192.168.1.100
docker compose up -d --build --wait
```

После появления домена замените `APP_ADDRESS` в `.env` на имя домена без `http://`, например
`home.example.org`, установите `COOKIE_SECURE=true` и выполните `docker compose up -d`. Caddy
запросит и будет обновлять TLS. Скрипт `setup-env.sh` сам включает защищённые cookies, если при
первой установке ему передано доменное имя вместо HTTP-адреса.

## Пользователи и общий планшет

- Взрослому выдаётся случайный временный пароль; при первом входе он обязан заменить его.
- Для ребёнка обязательную смену временного пароля определяет администратор при создании.
- Сброс пароля, отключение учётной записи и команда завершения сессий немедленно аннулируют
  действующие входы пользователя.
- Для общего планшета администратор задаёт PIN нужным участникам, регистрирует текущий браузер как
  доверенный и включает режим выбора пользователя по аватару.
- Периоды отсутствия и временный заместитель настраиваются в карточке участника. Использование этих
  периодов подключено к очередям задач: отсутствующий автоматически пропускается, а заданный
  заместитель временно получает его очередь.

## Дела

- В «Все дела» взрослый создаёт разовое или повторяющееся дело, выбирает одного/нескольких
  ответственных, режим «любой» или круговую очередь.
- Повторы поддерживают ежедневные, недельные, месячные, годовые, интервальные, календарные и
  сезонные правила. Одновременно открывается только один экземпляр серии.
- Результат ребёнка может ждать проверки взрослым. Отклонение требует комментария.
- «Сегодня» получает данные из API, сортирует дела по сроку, хранит выбор «Мои / Все» на устройстве
  и считает прогресс только по задачам.

## Покупки

- Списки бывают общими без даты или запланированными на конкретный поход/заказ. Только
  запланированный на сегодня список появляется в «Сегодня».
- Позиции группируются по получателю: сначала текущий пользователь, затем общее и остальные члены
  семьи. Дополнительные поля скрыты до раскрытия строки.
- Предложение ребёнка попадает в отдельную очередь взрослого и появляется в списке только после
  принятия. API предупреждает о совпадающих активных позициях и предлагает часто покупаемые товары.
- Добавление и отметка покупки сохраняются на устройстве без сети с уникальным ключом операции и
  повторяются после reconnect без создания дублей.
- При завершении списка взрослый выбирает: оставить некупленное без даты, перенести в другой список
  или удалить.

## Кладовая

- Разделы образуют дерево любой глубины. На компьютере доступно дерево, на телефоне — хлебные
  крошки; вещи и дочерние разделы могут находиться на каждом уровне.
- Поиск работает от корня, по текущей ветке или только текущему уровню и всегда показывает полный
  путь. Недавно открытые разделы доступны офлайн только для чтения.
- Перемещение меняет текущее место и начинает новый отсчёт времени в нём, но не меняет крайний срок
  хранения. «Использовано сегодня» обновляет только дату использования.
- Для раздела вручную создаётся защищённая ссылка QR. Она не зависит от содержимого и меняется
  только по команде «Пересоздать QR»; отрисовка и скачивание выполняются локально в PWA.
- По истечении таймера worker помечает вещь «Нужно решить» и идемпотентно создаёт обычное дело.

## Дом и обслуживание

- Оборудование хранится отдельно либо связывается с карточкой кладовой. При связи название,
  фотографии, место, производитель и гарантия читаются из кладовой и не дублируются.
- Просроченный регламент создаёт одно обычное дело. После выполнения обновляется следующая дата и
  появляется запись с комментарием, стоимостью и фотографиями.
- Ремонты хранятся два года от даты работ либо бессрочно по явному флажку; worker окончательно
  удаляет истёкшие записи без предварительного уведомления.
- Показания счётчиков сохраняются бессрочно, расход считается на сервере, уменьшение требует
  подтверждения. Замена начинает новый цикл, не удаляя старую историю.
- Администратор может скрыть модуль счётчиков. Данные остаются в базе и возвращаются при включении.

## Календарь, уведомления и настройки

- Календарь объединяет дела, покупки, обслуживание, показания, гарантии и таймеры хранения. Есть
  месяц, неделя, день, список и фильтры; повтор при переносе требует выбрать экземпляр или серию.
- Семейные карточки показывают нейтральную сводку дел, очередей, проверок и детских запросов без
  рейтингов и соревнования.
- Центр уведомлений создаётся worker-ом с дедупликацией. Персональные правила включают события,
  время опережения, повтор, тихие часы, Web Push и необязательный SMTP.
- Оформление, размер текста и плотность хранятся на сервере. Отключаемые модули только скрывают
  интерфейс и уведомления — предметные данные остаются в базе.

## Realtime, офлайн и конфликты

- Авторизованный клиент получает семейные изменения через Server-Sent Events и обновляет открытый
  экран без перезагрузки страницы. События имеют постоянный монотонный номер и переживают restart.
- «Сегодня» кэшируется для чтения; завершение дела и операции похода за покупками складываются в
  локальную очередь с уникальным ключом и повторяются после reconnect. Последние разделы кладовой
  доступны только для чтения.
- Без сети запрещены пользователи, настройки, резервные копии, файлы, QR и глобальный поиск
  кладовой. Этот список намеренно не расширяется универсальной очередью запросов.
- Изменения разных полей безопасно объединяются. При изменении одного поля сервер сохраняет своё
  значение и отдельную альтернативу; карточка становится красной, а взрослый выбирает серверный,
  альтернативный или введённый вручную вариант в «Настройки → Конфликты».
- Пять неразрешённых конфликтов создают одно уведомление администратору. Альтернативы никогда не
  принимаются и не удаляются автоматически; администратор может отклонить их все одной командой.

## Проверка сохранности данных

Сквозной скрипт поднимает проект, проверяет health endpoints и миграцию, создаёт контрольную запись,
перезапускает PostgreSQL и подтверждает, что запись сохранилась:

```bash
./scripts/verify-stack.sh http://localhost
```

Скрипт не удаляет контейнеры и volumes. Остановить сервисы без удаления данных:

```bash
docker compose down
```

## Локальная разработка

Нужны Python 3.12+, Node.js 24+ и npm.

```bash
make install
make check
```

Отдельный frontend dev server:

```bash
npm --prefix apps/frontend run dev
```

API локально ожидает PostgreSQL по `DATABASE_URL`. Миграции и запуск:

```bash
cd apps/api
../../.venv/bin/alembic upgrade head
../../.venv/bin/uvicorn app.main:app --reload
```
