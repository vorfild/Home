# Отчёт релизной проверки 1.0.0

Дата локального прогона: 1 августа 2026 года. Релизный gate: `./scripts/release-check.sh`.

## Автоматические проверки

| Контур | Результат |
|---|---|
| Ruff и ESLint | Пройдено без предупреждений |
| mypy и строгий TypeScript | Пройдено |
| Backend API/доменные тесты | 40 пройдено |
| Frontend component/offline тесты | 10 пройдено |
| Production PWA build | Пройдено |
| Чистая Alembic-миграция `0001` → `0010` | Пройдено на SQLite |
| Shell syntax | Пройдено для всех `scripts/*.sh` |
| Compose structure | Пять сервисов и постоянные volumes проверены статически |

Backend-набор покрывает первый запуск и гонку singleton, роли/CSRF, временный пароль, PIN и
отзыв сессий; повторы/очереди/проверку дел; предложения и офлайн-идемпотентность покупок; дерево,
поиск, QR и таймер кладовой; обслуживание/счётчики; календарь/уведомления; конфликты SSE; приватные
файлы, tamper detection, экспорт/импорт; справочники, архив, корзину, восстановление QR и worker
purge.

## Заявленный объём

`python3 scripts/load-check.py` создаёт 20 пользователей, 50 000 карточек кладовой, 100 000
завершённых и 10 000 открытых экземпляров дел, проверяет количества и индексированные запросы
поиска, раздела кладовой, «Сегодня» и открытых дел участника. Порог каждого запроса — 3 секунды;
фактические времена печатаются JSON, чтобы регрессия была видна в CI и на сервере.

## Проверка реального сервера

На Linux-хосте с Docker необходимо дополнительно выполнить:

```bash
./scripts/verify-stack.sh http://localhost
```

Он собирает и ждёт пять сервисов, проверяет health endpoints и миграции, записывает контрольное
значение, перезапускает PostgreSQL и подтверждает сохранность volume. После этого вручную проверяют
узкий/широкий экран, клавиатурную навигацию, фото/HEIC/PDF, Push (если настроен), экспорт на другое
устройство и восстановление на тестовой копии.
