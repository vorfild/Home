# Установка и обновление сервера

## Первый запуск по IP

Нужен Linux-сервер с Docker Engine, Compose v2, Git и открытым портом 80. Клонируйте репозиторий и
создайте закрытый `.env`; токены и пароли в команды или issue не копируйте.

```bash
git clone https://github.com/vorfild/Home.git
cd Home
./scripts/setup-env.sh http://192.168.1.100
docker compose up -d --build --wait
./scripts/verify-stack.sh http://localhost
```

Откройте `http://192.168.1.100` и пройдите мастер. PostgreSQL, файлы, архивы и состояние Caddy
хранятся в именованных volumes. Для обычной остановки используйте `docker compose down`; параметр
`-v` удаляет данные и в инструкциях не применяется.

## Подключение домена и HTTPS

Создайте DNS A/AAAA-запись домена на сервер, откройте 80/TCP и 443/TCP+UDP. В `.env` задайте домен
без схемы и включите защищённые cookies:

```dotenv
APP_ADDRESS=home.example.org
COOKIE_SECURE=true
```

Затем примените конфигурацию и дождитесь health-check:

```bash
docker compose up -d --wait
docker compose ps
```

Caddy автоматически получает и обновляет сертификат. После проверки входа по HTTPS закройте
прямой доступ к приложению по IP на внешнем firewall, оставив SSH только с доверенных адресов.

## Обновление

Сначала в «Настройки → Данные» подготовьте обновление: система проверит пароль администратора и
создаст страховочный архив. В устойчивой SSH-сессии (`tmux`/`screen`) запустите выданную команду:

```bash
./scripts/update-server.sh v1.0.0
```

Скрипт отказывается работать с незакоммиченными изменениями, фиксирует текущий commit и путь
архива, скачивает только указанный ref, собирает контейнеры, ждёт health-check и запускает
сквозную проверку. При ошибке он восстанавливает physical PostgreSQL dump, файлы и прежний commit.
Повторить сохранённый откат вручную:

```bash
./scripts/rollback-server.sh
```

После успешного обновления проверьте вход, «Сегодня», файлы и статус месячной копии. Сохранённое
состояние rollback можно оставить до следующего подтверждённого обновления.
