# Модель безопасности

## Границы доверия

Домовой рассчитан на один доверенный семейный сервер. Интернет, браузер, загружаемые файлы,
переносимый ZIP и значения API считаются недоверенными. PostgreSQL, volumes и SSH-аккаунт сервера
считаются административной границей: получивший root-доступ к хосту может читать данные установки.

| Возможность | Ребёнок | Взрослый | Администратор |
|---|---:|---:|---:|
| Читать назначенные дела, семейные списки и разрешённые файлы | Да | Да | Да |
| Выполнять своё/общее дело, предлагать покупку | Да | Да | Да |
| Создавать дела, списки, кладовую и обслуживание | Нет | Да | Да |
| Менять комнаты и категории | Нет | Да | Да |
| Разбирать конфликты | Нет | Да | Да |
| Пользователи, PIN, планшеты, сервер и импорт | Нет | Нет | Да |
| Корзина, восстановление и безвозвратная очистка | Нет | Нет | Да |

Права проверяются в зависимостях и обработчиках FastAPI. Все запросы ограничиваются
`household_id`; доступ к файлу дополнительно повторяет проверку связанной записи. UUID и QR не
являются авторизацией.

## Учётные данные и сессии

Пароли и PIN хешируются Argon2id. Сессионный и планшетный токены генерируются CSPRNG; в базе
хранится только keyed digest. Сессия передаётся в HttpOnly `SameSite=Strict` cookie, изменяющий
запрос требует отдельную CSRF cookie, совпадающий заголовок и digest сессии. На домене обязательно
`COOKIE_SECURE=true` и HTTPS. Ограничение попыток не раскрывает существование логина.

Отключение пользователя, сброс пароля и импорт отзывают активные сессии. Секреты создаются с
режимом файла 600, исключены из Git и не выводятся в структурированные логи.

## Файлы, ZIP и HTTP

Загрузка ограничена 25 МБ, набором расширений, MIME и magic bytes. Декодирование изображения имеет
лимит пикселей; имя очищается до basename. ZIP проверяется до извлечения: запрещены абсолютные и
родительские пути, ограничены число записей и суммарный несжатый размер, сверяются SHA-256.

Caddy завершает TLS и задаёт CSP, запрет MIME sniffing и frame embedding. API добавляет
`Cache-Control: no-store` ко всем обычным приватным ответам; SSE использует `no-cache`. Файлы
требуют активную сессию и повторную проверку права на связанную запись. Web Push и SMTP являются
необязательными внешними каналами и не получают пароли или полный архив.

## Операционные меры

- Ограничьте SSH по ключам и firewall, обновляйте Docker/ОС, не публикуйте PostgreSQL наружу.
- Храните ручную копию вне сервера и периодически проверяйте восстановление на отдельной установке.
- Не вставляйте секреты в issue, чат, командную историю или скриншоты.
- Перед обновлением используйте страховочную копию и сохранённый rollback.
- Сообщения о проблемах безопасности отправляйте владельцу установки приватно, не через публичный
  issue с данными семьи.
