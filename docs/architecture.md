# Архитектура «Домового»

## Обзор

«Домовой» разворачивается как монорепозиторий и один Docker Compose-проект для одной семьи. На
Этапе 1 заложены пять сервисов без внешнего оркестратора и без Redis.

| Сервис | Назначение | Доступ извне |
| --- | --- | --- |
| `proxy` | Caddy, единая HTTP/HTTPS-точка входа | 80/TCP, 443/TCP и 443/UDP |
| `frontend` | собранное React PWA, выдаваемое Nginx | нет |
| `api` | версионируемый FastAPI `/api/v1` | нет |
| `worker` | фоновые периодические и служебные задания | нет |
| `database` | PostgreSQL | нет |

Все сервисы находятся в закрытой bridge-сети Compose. Caddy направляет `/api/*` и `/health/*` в
API, остальные запросы — во frontend.

## Структура репозитория

```text
apps/
  api/                 FastAPI, SQLAlchemy, Alembic и worker
  frontend/            React, TypeScript, Vite и PWA
deploy/caddy/           Конфигурация reverse proxy
docs/                   Спецификация, архитектура и дизайн-референс
scripts/                Подготовка окружения и сквозная проверка Compose
compose.yaml             Production-like локальная оркестрация
```

## Серверная часть

API использует асинхронный SQLAlchemy и драйвер `asyncpg`. Миграции Alembic запускаются
entrypoint-скриптом до старта Uvicorn, поэтому API не начинает принимать запросы со старой схемой.
Готовность проверяется отдельным запросом `SELECT 1`; liveness не зависит от базы.

Worker собирается из того же Python-образа, но запускает отдельный процесс. На первом этапе он
делает устойчивую к ошибкам проверку базы по таймеру. Доменные расписания добавляются последующими
этапами без объединения worker с веб-процессом.

Первая миграция создаёт `system_metadata`. Она служит минимальной постоянной записью схемы и
проверкой сохранности PostgreSQL volume.

## Клиент

Клиент — React PWA со строгим TypeScript. Manifest и service worker формируются Vite PWA plugin.
Приложение использует локально поставляемые Manrope и Inter, дизайн-токены из спецификации,
системную тёмную тему, адаптивную боковую/нижнюю навигацию, клавиатурный фокус и
`prefers-reduced-motion`.

Русские интерфейсные строки собраны в `src/lib/i18n.ts` как начальная граница будущей локализации.
Показанные на первом этапе данные — интерактивные демонстрационные данные shell; доменные данные и
авторизация подключаются на Этапах 2–4.

## Данные и volumes

- `database_data` — PostgreSQL;
- `user_files` — пользовательские вложения;
- `backup_data` — месячные и ручные архивы;
- `caddy_data`, `caddy_config` — сертификаты и внутреннее состояние Caddy.

Удаление контейнеров не удаляет volumes. Команда `docker compose down -v` является разрушительной и
не используется в инструкциях обновления.

## Конфигурация и секреты

Compose имеет безопасные для локальной проверки значения по умолчанию, однако установка на сервер
обязана сначала выполнить `./scripts/setup-env.sh http://IP`, который создаёт `.env` с режимом 600 и
криптографически случайными значениями. `.env` исключён из Git.

`APP_ADDRESS=http://IP` оставляет HTTP для первого запуска. Значение вида `home.example.org`
переключает Caddy на автоматический публичный TLS. Полный безопасный сценарий подключения домена,
перенаправления IP и обновления относится к Этапу 9.

## Наблюдаемость

Python пишет структурированные JSON-логи в stdout. В них не должны попадать секреты и приватные
данные. Compose health checks проверяют PostgreSQL, API, worker и frontend; proxy запускается только
после готовности upstream-сервисов.
