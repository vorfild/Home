# Резервные копии, экспорт и восстановление

## Что находится в архиве

Архив Домового — ZIP с `manifest.json`, переносимым `database.json` и каталогом `files/`.
Манифест содержит версию приложения и Alembic-схемы, количество строк каждой таблицы и SHA-256
каждого содержимого. В PostgreSQL-установке архив также содержит `database.pgcustom`: он нужен для
точного отката схемы после неуспешного обновления.

В снимок входят пользователи и Argon2id-хеши, задачи и история, покупки, кладовая, стабильные QR,
обслуживание, настройки, уведомления, конфликты и метаданные файлов. Исходные пароли, PIN, cookie и
исходные токены сессий не хранятся в базе и потому не могут попасть в экспорт.

## Месячная и ручные копии

Worker создаёт копию при первом успешном цикле каждого календарного месяца. В `monthly/` всегда
один целевой ZIP: временный архив полностью создаётся и проверяется, затем заменяет старый через
атомарный `rename`. При любой ошибке старая копия остаётся.

Ручной экспорт создаётся в «Настройки → Данные». Такие ZIP лежат в `manual/` и автоматически не
удаляются. Страховочные копии импорта и обновления лежат в `insurance/`.

Рекомендуется регулярно скачивать ручной архив на другое физическое устройство. Отдельный Docker
volume защищает от ошибки приложения, но не от потери диска сервера.

## Импорт через интерфейс

1. Войдите администратором и откройте «Настройки → Данные».
2. Выберите ZIP и подтвердите действие текущим паролем администратора.
3. Система проверит пути, формат, совместимость и все контрольные суммы.
4. До изменения данных будет создана страховочная копия текущего состояния.
5. Данные и файлы заменятся как одна операция; количества сравнятся с манифестом.
6. После отчёта все сессии будут отозваны. Войдите повторно.

Приложение текущей версии принимает архивы известных более ранних схем и восстанавливает их в уже
последовательно мигрированную базу. Архив новой неизвестной схемы отклоняется. Стабильные QR-токены
восстанавливаются как данные, поэтому прежние напечатанные метки продолжают работать.

## Аварийное восстановление из SSH

Остановите API и worker, затем запустите доверенную локальную CLI-команду внутри контейнера. Для
PostgreSQL она предпочитает physical dump; для тестовой SQLite-среды используется логический снимок.

```bash
docker compose stop api worker
docker compose run --rm --no-deps --entrypoint python api \
  -m app.backup_cli restore --archive /data/backups/insurance/ИМЯ.zip
docker compose up -d --wait
./scripts/verify-stack.sh http://localhost
```

Восстановление отзывает сессии. Не извлекайте ZIP вручную поверх volumes: так можно получить базу и
файлы из разных моментов времени.
